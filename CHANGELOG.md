# Changelog

## 0.1.0 (unreleased)

First public version.

- Daemon with per-chat sessions for Telegram, Discord, Slack and LINE, plus a web dashboard and HTTP API.
- Providers: `claude-tmux`, `claude-sdk`, `codex`, `opencode`, `acp`, `agy`, `pi`.
- Provider-independent message bus exposed to agents over MCP (`agents_list`, `agent_ask`, `agent_trigger`, `notify`, `task_status`, `cron_*`, `worker_*`), and A2A v1.0.
- Every DM is its own session; heartbeat and cron jobs run in their own internal sessions with per-job profile/model.
- Workers: start another coding agent in a chosen directory and take it over from chat (`/attach`) or a terminal (`uniqlaw attach`).
- Credentials layer (API keys, Bedrock, Vertex AI, Azure, provider logins) with secrets stored by reference only.
- Memory: `memory/MEMORY.md` + daily notes, `memory_write` / `memory_search` / `memory_get` for every provider, CJK-capable full-text search; Claude Code's auto-memory is turned off while it is on.
- Dreaming plugin (after OpenClaw): nightly promotion of daily notes into `MEMORY.md` with rule-based gates and model-chosen add / merge / supersede / skip, validation and history; dream diary; `uniqlaw dream [--dry-run]`.
- `/profile [name|reset]`: switch a chat to another profile. Same-provider (and claude-tmux ↔ claude-sdk) switches keep the session; otherwise the conversation is handed over as raw transcript (`profileSwitch.handoffMaxChars`), and switching back resumes the earlier session with what ran meanwhile. On a usage limit the owner is asked whether to switch to a `fallback` profile (the failed message is re-sent); others get the error.
- Voice transcription (optional, `transcription.engine`): `whisper` (local whisper.cpp via `@fugood/whisper.node`, audio decoded with ffmpeg) or `transcribe-api` (OpenAI-compatible `/audio/transcriptions`). By default only for providers that can't take audio; the transcript is added to the message and the file stays attached. Off by default: the agent handles audio files itself.
- DM pairing (after OpenClaw): a stranger who DMs the bot gets a one-time code; an operator approves it with `/pair approve <code>` or `uniqlaw pairing approve <code>`. Paired users live in `state.db`, are accepted like `allowedUserIds` but are never operators, and can be removed with `uniqlaw pairing revoke`. Open requests are capped (`pairing.maxPending`) and expire (`pairing.ttlMinutes`); `pairing.enabled: false` turns it off.
- `send_file` bus tool: agents post local files (image, audio, voice note, video, document) to their own or another chat without calling platform APIs. Telegram, Discord and Slack (needs the `files:write` scope); limited to the project, the session's directory, the temp dir, `workers.roots` and `files.roots`, up to `files.maxMB`.
- Fix: `uniqlaw <command> --help` / `-h` now prints that command's usage and exits 0 without doing anything (before, every command but `init` ignored it, so `uniqlaw stop --help` stopped the daemon). `uniqlaw help <command>` does the same. Unknown options (`--x` or `-x`) are rejected with exit 2 instead of being ignored; a bare `--` ends option parsing (e.g. `uniqlaw send <target> -- --text`).
- Fix: the stall watchdogs no longer fail a turn that sits in one long tool call (waiting on CI, a long test run). A quiet turn is abandoned only when there is no liveness signal at all (no tool call in flight; for claude-tmux also no jsonl write, no pane change, no busy spinner or dialog); new `turn.stallMaxSec` (default 7200) is the hard ceiling for a hung agent, and each stall logs the signals it checked. Providers can report signals through the optional `AgentSession.liveness()`.
- Fix: claude-tmux could exit with status 1 when a worker started in an untrusted folder. The folder-trust handler only recognised the numbered layout (`❯ 1. Yes, I trust this folder`); on the current unnumbered one (cursor on "No, exit") it sent a blind Down+Enter, and `waitForReady` sent it again while the dialog was still drawn, so the second Down wrapped back to "No, exit". Startup menus are now answered by where the cursor actually is (moved to the option, checked, then Enter), and the same screen is not answered twice.
- Fix: several `agent_ask`s from one session that end up in one turn (steered in, or merged from the queue) no longer each get the turn's whole answer. The earliest gets it once, listing the others; each later one resolves with `merged into task <id>; result delivered there` and, if async, is not delivered separately. Before, 7 asks steered into one long turn delivered the same ~6 KB answer 7 times at once. Asks from different sessions still each get the whole answer.
- Fix: a per-channel `groups.channels.<key>` entry no longer resets unset fields (`mode`, `historyLimit`, `ignoreOtherMentions`, `allowFrom`, `others`) to their defaults; they come from the global `groups` settings.
- Group modes: `mention` (default; unaddressed messages are kept as context for the next turn) or `always`, with `ignoreOtherMentions`, per-channel settings (`groups.channels`) and `/activation`. Discord's v2 per-channel `requireMention` / `ignoreOtherMentions` map onto them; unaddressed messages are no longer dropped.
- Per-channel capabilities (`channels`): each chat gets tool groups (`chat`, `memory`, `web`, `files.read`, `files.write`, `bash`, `agents`, `cron`, `worker`, `xsession`, `notify`, `config`; `"*"`, `deny`). The MCP gateway only lists and accepts the granted tools; claude-tmux / claude-sdk get matching `--tools` / `--disallowedTools`, plus `--strict-mcp-config` for any policy (deny mode too: the user's own MCP servers belong to no group); `ToolSearch` stays in deny mode and, in allow mode, while any UniQlaw MCP group is granted; other providers refuse to open a chat whose built-in tools are restricted. A policy change respawns a reattached claude-tmux session. No `defaults` entry = unrestricted, so existing installs keep their behavior.
- Admin-level tool groups (`bash`, `files.write`, `cron`, `worker`, `xsession`) are documented as full access and warned about at startup when a restricted chat gets one; restricted chats can't read `.uniqlaw/` with Claude's file tools.
- Group wake rules: `groups.allowFrom` (platform user ids allowed to wake the agent, checked in core on the immutable id) and `groups.others` (`context` / `ignore` for messages that don't wake it).
- Delegation hops: an async `agent_ask` / `worker_start` result re-enters the asking session at its own hop, and a human message starts a new chain at hop 0, so a chat can do more than two rounds with its worker. Result-driven rounds are capped by `bus.maxRounds` (default 20, reset by a human message); nested ask loops still stop at `bus.maxHops`. Fan-out is capped by `bus.maxPending` (outstanding async tasks per session, default 8) and `bus.maxChainTasks` (delegation calls per human-started chain, default 50).
- `task_status` reports `elapsedSec` and, while the task is open, `progress`: whether the answering session is running it or has it queued, the latest assistant text (also mid-stream) and its last activity lines.
- A2A hardening: inbound sessions are keyed by the authenticated caller (`a2a:<profile>:<caller>:<contextId>`), so a peer reusing another peer's `contextId` no longer joins its session; tasks are visible to their creator only; inbound A2A sessions are deny-by-default (permissions capped at `strict`, and a fixed tool policy over the channel tool groups that denies every group but `web`: no shell, file, sub-agent, cron, worker, cross-session, notify / `send_file`, memory or config tools, whatever `channels` says); a named bearer token can be limited to some profiles (`profiles`), others answer 403; token names must be unique. Inbound A2A sessions are isolated: empty working directory outside the project, no built-in tools, no operator settings / CLAUDE.md / MCP servers / native memory, and the exposed profile's own `prompt` / `promptFiles` instead of the persona files. Only providers that can isolate them (claude-tmux, claude-sdk) can be exposed unless `unsafeProvider: true`. Anonymous mode (no tokens) logs a warning.
- Agent-guided migration from ClaudeClaw v2 (`docs/MIGRATE.md`), including importing Claude auto-memory.
- Graceful restart / reload (`uniqlaw restart [--in|--at] [--now] [--cancel]`, `uniqlaw reload`, `POST /api/restart`, the `daemon_restart` tool for the operator's chat, in the `config` tool group, so a restricted chat needs `config` and inbound A2A sessions never get it): the request returns at once, running turns finish (`restart.drainTimeoutSec`), new messages, async results and due cron jobs are kept in `state.db` and replayed after it, open `agent_ask` tasks are re-armed or failed with a reason, and the requesting session plus every session whose turn was cut off get a `[uniqlaw]` notice as a new turn (claude-tmux sessions too, after their resumed turn). Held messages are at-least-once (kept in `state.db` until the turn that answers them starts); a turn a restart cut off on claude-sdk/codex has its message re-sent; claude-tmux replies written while the daemon was down are delivered on reattach. `restart` starts a new process and only exits once it is up — otherwise the old process starts again on its current code; under a systemd service it exits 75 for the supervisor. `SIGTERM` records interrupted turns for the next start.

### Fixes

- claude-tmux: a permission dialog that opened while the daemon was down (pane neither busy nor ready on reattach) was never forwarded, so the turn stalled for `turn.stallTimeoutSec`. It is now detected on the first poll and sent to the operator.
- claude-tmux: a reattached claude whose launch flags no longer match the profile (permission mode, model, tools, …) is respawned with `--resume` once idle; the conversation is kept. The flags are fingerprinted per session at spawn.
- A turn still running when the daemon stops or reloads now keeps its reply: the session is reopened on startup and the reply goes to the chat that asked. Also fixes `this.turn.toolBubble` errors when a turn ends while a tool status is being posted.
- CLI commands find the project from any subdirectory, including `.uniqlaw/` itself (`init` still uses the current directory).
